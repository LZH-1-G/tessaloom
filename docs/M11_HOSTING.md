## Independent Mac POC

`deploy/compose.tunnel.yml` replaces (does not append) the proxy ports with **127.0.0.1:18080** and uses `Caddyfile.tunnel`. It requires Compose >= 2.24.4 for `!override`. It starts neither Tailscale nor Cloudflare. The same production app, fixture guard, invitation policy, worker-only credentials and DB TLS remain intact. The automated smoke tests this origin using an internal Docker client and checks the loopback port configuration.

TLS would terminate in the connector; Caddy forwards the original Host, sets forwarded scheme HTTPS and streams without buffering. It discards visitor IP assertions, including CF-Connecting-IP. App trust stays at one hop: all tunnel traffic may share one IP throttle bucket. This is conservative but can block multiple judges after failed codes. Do not increase trusted hops or whitelist visitor-supplied IP headers to fix it; a future per-client design needs a separately tested connector trust boundary.

After separate public-exposure approval, an operator can set `TLS_DOMAIN` to the actual `ts.net` or Cloudflare hostname, start the loopback origin, and connect **only** `http://127.0.0.1:18080`. Never expose Docker ports 3000/5432, a directory, Docker socket or the private deployment directory. Confirm the connector preserves the public Host; for Cloudflare set its HTTP Host Header to the same reviewed hostname if needed. Set caching to bypass authenticated/API/share content. Inspect edge log retention because URLs may include share tokens even when our Caddy logs omit them.

For an approved Funnel trial, use the [official CLI](https://tailscale.com/docs/reference/tailscale-cli/funnel): `tailscale funnel --https=443 http://127.0.0.1:18080`, initially in the foreground; stop with Ctrl-C and verify status. Do not use `--bg` until persistent public sharing is approved: it resumes across reboots. For named Cloudflare use its dashboard's OS-specific install procedure and private credential storage; do not put a connector token in repository files or public instructions. Removing the route/stopping that connector is the exposure rollback. No connector command has been executed here.

Before considering either viable: verify Mac sleep/reboot/login and Docker autostart behavior, stable ISP/power, off-host backup recovery, public browser Host/CSRF/Secure-cookie behavior, SSE progress/reconnect/cancel, anonymous denial, provider-zero counters, domain/cert continuity and private-port denial from another network. Actual tunnel transport, public TLS and external reliability remain **UNTESTED**. A successful local origin POC is not a public tunnel or hosting-compliance test.
